## 题目：面试官只给了一分钟

一道经典的面试题：

> 给定一个**非空**整数数组 `nums`，其中恰好有一个元素只出现一次，其余所有元素均出现**两次**。找出那个只出现一次的元素。要求时间 O(n)、额外空间 O(1)。

稍微变形一下：

> 其余所有元素均出现**三次**，找出唯一出现一次的元素。

别看题目简单，它几乎能一次性考到：哈希表、位运算、二进制思维。这篇文章从暴力解讲到位运算进阶，顺便把面试里常用的位运算技巧全部盘一遍。

## 第一版：HashMap 计数，能过但不够漂亮

拿到题目第一反应是计数：

```java
public int singleNumber(int[] nums) {
    Map<Integer, Integer> count = new HashMap<>();
    for (int n : nums) {
        count.put(n, count.getOrDefault(n, 0) + 1);
    }
    for (Map.Entry<Integer, Integer> e : count.entrySet()) {
        if (e.getValue() == 1) {
            return e.getKey();
        }
    }
    throw new IllegalArgumentException("输入不合法");
}
```

时间 O(n) 满足，但空间 O(n)——HashMap 要存一半以上的元素。面试官问："能不能把空间压到 O(1)？"

这就得请出位运算了。

## 核心武器：异或

先复习三条异或性质（Java 里是 `^`）：

| 性质 | 表达式 | 直觉 |
| --- | --- | --- |
| 归零律 | `a ^ a = 0` | 自己异或自己，所有位抵消 |
| 恒等律 | `a ^ 0 = a` | 异或 0 保持原值 |
| 交换律/结合律 | `a ^ b ^ c = a ^ c ^ b` | 顺序无关，随便换 |

**核心思想**：把数组里所有数全部异或一遍。出现两次的数成对抵消变 0，最后剩下的就是只出现一次的那个数。

```java
public int singleNumber(int[] nums) {
    int result = 0;
    for (int n : nums) {
        result ^= n;   // 全部异或，成对的归零
    }
    return result;     // 只剩唯一没成对的
}
```

验证一下：`nums = [4, 1, 2, 1, 2]`：

```text
4 ^ 1 ^ 2 ^ 1 ^ 2
= 4 ^ (1 ^ 1) ^ (2 ^ 2)   // 交换律，把成对的放一起
= 4 ^ 0 ^ 0
= 4
```

时间 O(n)、空间 O(1)，几行代码解决。面试官一般会满意地点头，然后抛出第二个问题："如果其他数都出现**三次**呢？异或还行不行？"

试一下：`[3, 3, 3, 5]`，`3 ^ 3 ^ 3 ^ 5 = 3 ^ 5 = 6`，答案错了。因为异或抵消只对"偶数次"有效。

## 进阶：其他数出现三次，逐位统计 %3

换个思路：不看整个数，看**每一位**。

对数组里的每个数，统计每个二进制位上 1 出现的次数。如果某一位的 1 出现了 `3k + 1` 次，说明唯一那个数在这一位上是 1；如果是 `3k` 次，说明怪数这一位是 0。

```java
public int singleNumber2(int[] nums) {
    int result = 0;
    // int 是 32 位，逐位处理
    for (int i = 0; i < 32; i++) {
        int bitCount = 0;
        for (int n : nums) {
            bitCount += (n >> i) & 1;   // 取出第 i 位（0 或 1）累加
        }
        result |= (bitCount % 3) << i;  // 余 1 说明怪数该位为 1
    }
    return result;
}
```

以 `nums = [3, 3, 3, 5]` 为例，只看后三位：

| 数（二进制） | bit2 | bit1 | bit0 |
| --- | --- | --- | --- |
| 3 = 011 | 0 | 1 | 1 |
| 3 = 011 | 0 | 1 | 1 |
| 3 = 011 | 0 | 1 | 1 |
| 5 = 101 | 1 | 0 | 1 |
| 1 的个数 | 1 | 3 | 4 |
| % 3 | **1** | 0 | **1** |

结果 bits = 101 = 5，正确。这个算法的复杂度是 O(32n) = O(n)，空间 O(1)。

> 面试加分项：推广到"其他数都出现 k 次"，把 `% 3` 换成 `% k` 即可，本质是**用二进制模拟 k 进制计数器**。更高级的写法是用 `ones`、`twos` 两个变量做状态转移，硬核面试官可能会追问，这里不展开。

## 位运算技巧汇总表

题目做完，把日常最高频的位运算技巧整理成表（n 为 int，k 为位数）：

| 需求 | 表达式 | 说明 |
| --- | --- | --- |
| 判断奇偶 | `(n & 1) == 1` | 比 `n % 2` 快，只看最低位 |
| 判断 2 的幂 | `(n & (n - 1)) == 0` | 2 的幂二进制只有一个 1 |
| 交换两个数 | `a ^= b; b ^= a; a ^= b;` | 不用临时变量，面试炫技但实际别这么写 |
| 取低 k 位 | `n & ((1 << k) - 1)` | 掩码操作 |
| 清零最低位的 1 | `n & (n - 1)` | 统计 1 个数的核心 |
| 取最低位的 1 | `n & (-n)` | 树状数组 lowbit 的由来 |
| 对 2 的幂取模 | `n & (k - 1)` | k 必须是 2 的幂，如 `n % 16` → `n & 15` |
| 判断正负 | `(n >> 31) != 0` | 负数最高位（符号位）是 1 |

```java
// 实际执行验证一下
int n = 12;                       // 1100
System.out.println(n & -n);       // 4    -> 最低位 1 的权值
System.out.println(n & (n - 1));  // 8    -> 1100 & 1011 = 1000，清掉了最低位的 1
```

## 面试延伸：统计二进制中 1 的个数

题目做完，再来一道面试加试题：**统计整数二进制里有多少个 1**。

最直观——逐位检查：

```java
public int countOnes(int n) {
    int count = 0;
    while (n != 0) {
        count += (n & 1);  // 看最低位
        n >>>= 1;          // 无符号右移
    }
    return count;
}
```

更快——用 `n & (n - 1)` 每次消掉一个 1，循环次数 = 1 的个数：

```java
public int countOnes(int n) {
    int count = 0;
    while (n != 0) {
        n = n & (n - 1);   // 干掉最低位的 1
        count++;
    }
    return count;
}
```

n = 12（1100）的话：第一次变成 1000，第二次变成 0，循环两次，答案 2。Java 里其实有现成的 `Integer.bitCount(n)`，面试时可以提一句"生产环境直接用 JDK 的 `Integer.bitCount`"，体现工程意识。

## 一道题，一串收获

回头再看看这道"找单独的数"：

| 版本 | 解法 | 复杂度 | 考点 |
| --- | --- | --- | --- |
| 出现两次 | 异或全消 | O(n) / O(1) | 异或性质 |
| 出现三次 | 逐位统计 %3 | O(n) / O(1) | 位运算 + 计数思想 |
| 计数版 | HashMap | O(n) / O(n) | 基础实现，用来对比 |

位运算的难点从来不是运算符本身，而是**把问题翻译成二进制视角**：出现两次 → 异或抵消；出现三次 → 逐位计数；求 1 个数 → lowbit 清零。把一个"数"看成 32 个独立开关，很多难题会一下子变得清晰起来。
